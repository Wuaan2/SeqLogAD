# P2.3 — Lightweight Sequence Expert (LIGHT-SEQ-001) preregistration

Status: frozen before any P2.3 run (2026-11-21). Config: `configs/models/sequence-lightweight-v1.yaml`.
Protocol: EXC-007 (target folds BGL and HDFS only), development seed 42.

## Question

Does a much cheaper explicit sequence model keep the next-log anomaly signal of the
P2.2 reference (Llama-3.1-8B + LoRA-Sequence, `LORA-SEQ-003-R1`)?

## Frozen design

| Item | P2.3 | P2.2 reference |
|---|---|---|
| Model | Causal Transformer with Llama decoder blocks (RMSNorm, RoPE, SwiGLU), random init | Llama-3.1-8B, NF4, LoRA r16 |
| Size | 4 layers, hidden 256, 4 heads, FFN 1024, tied embeddings, vocab 128256: 37,030,144 parameters (0.46% of 8,030,261,248) | 8.03B total, about 13.6M trainable |
| Pretrained weights | none | Llama-3.1-8B |
| Tokenizer, prompt, context (max 8 predecessor records, 512 tokens), crop policy | same | — |
| Training windows, multiscale context views [1, 2, 4], source balancing | same | — |
| Objective | `CAUSAL_NEXT_LOG_TARGET_TOKEN_NLL` (same) | — |
| Checkpoint selection, early stopping | macro source-development F1 (P3.1 amendment), patience 3 (same) | — |
| Optimizer | AdamW, lr 5e-4, warmup 200, max 3072 steps, grad accumulation 16, no weight decay | lr 1e-4, warmup 100, max 1536 steps |

The config inherits every field of the V13R1 reference and may override only the
architecture, learning rate, warmup and step budget (`load_config` enforces this).
So the two experts see identical information; they differ in capacity and pretraining.
The larger step size and budget are needed because the model starts from random weights.

## Resource criterion (preregistered)

- Pass condition: total parameters at most 1% of the reference (at most 80,302,612).
  The model build fails closed above this budget.
- Reported, not thresholded: trainable parameters, runtime, peak VRAM, validation
  seconds per window. Note that P2.3 trains more parameters (37.0M) than the LoRA
  (about 13.6M); it is lighter only in total and inference size.

## Capability comparison

Macro source-development F1 per fold is reported next to P2.2 with no pass
threshold. A worse result is a finding and is reported, not hidden.

## Boundaries

No target data or target labels. Source-validation labels are used only for
checkpoint selection, as in P2.2 V13R1. One seed (42); no stability claim; no winner
selection between P2.2 and P2.3 in this task.
