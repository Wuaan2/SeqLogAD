# P3.6 fusion baselines (FUS-BASE-001)

Spec: [`configs/protocols/fus-base-v1.yaml`](../../configs/protocols/fus-base-v1.yaml). Code:
`src/seqlogad/adaptation/baselines.py`. Tests: `tests/test_adaptation.py`.

Opened by the researcher on 2026-11-28 (workbook update P3.6-STATUS-001, K26 → In progress). On the same day the
researcher chose the three open designs: a Transformer encoder trained on the buffer, an Isolation Forest on
event counts fitted on the buffer, and the strongest single as an oracle upper bound. No target evaluation record had
been scored.

## Baselines

No baseline learns a target weight, and each has exactly one configuration, so none is tuned.

| Baseline | Score | Fitted on |
|---|---|---|
| `SINGLE_<expert>` × 4 | the expert's CAL-CS-001 calibrated score; none when the expert is UNKNOWN_REVIEW (UNC-CS-001) | nothing (frozen experts) |
| Strongest single | `ORACLE_UPPER_BOUND`: the best AP of the four singles per fold, in the locked final evaluation | chosen with labels, reported as a bound only |
| `EQUAL_WEIGHT` (mandatory, G2 = PARTIAL) | mean calibrated score over the SCORED experts; UNKNOWN_REVIEW below the quorum of 2 | nothing |
| `TRANSFORMER_ENCODER` | masked-record NLL of the target, with the target masked | the buffer's statistics windows only |
| `ISOLATION_FOREST` | minus `score_samples` on hashed message counts (1024 buckets, 200 trees, seed 42) | the buffer's statistics windows only |

The encoder is a 2-layer bidirectional Transformer (d_model 64, 4 heads, FFN 128, dropout 0.1, learned positions).
It reads the 9 records of a window as normalised-message ids, with PAD, MASK and UNK. Each window and epoch, one
record position is masked at random. The last 10% of the windows, in target-rank order, are the label-free
early-stopping set (AdamW, lr 0.001, batch 256, at most 20 epochs, patience 3, seed 42).

## Input access and eligibility

- The experts read the source training data and use the buffer only for calibration.
- The encoder and the forest read the buffer only.
- No baseline reads a target label or an evaluation record for fitting.
- A baseline is comparable on a fold when it scores the same evaluation windows of that fold.
- UNKNOWN_REVIEW windows are reported in the three UNC-CS-001 views.

## Predictions

- EVID-CS-001 accepts only the four frozen Phase-2 experts, so the predictions are a table that uses its key fields:
  `baseline_id, fold_id, target_rank, target_record_id, score_raw, score_direction, status, reason`.
- **Now:** the buffer windows are the example outputs. The encoder and the forest were fitted on these windows, so
  their rows are marked `in_sample`.
- **Final evaluation:** the target evaluation windows, scored once in the locked run (G4).

## Run (after CAL-CS-001 and UNC-CS-001 exist)

```
python -m seqlogad.adaptation.baselines build --root <data root> --repo-root .
```

A one-epoch smoke run on the real HDFS fold (nothing written) gave 899,183 encoder parameters, 6,444 vocabulary
messages, 8.6 s per epoch on CPU and 1.7 s for the forest. All seven baselines scored the 8,192 buffer windows.

## Result (2026-11-28)

Built on both folds and accepted by the researcher; hashes, budgets and findings are in
[`configs/protocols/p3.6-receipt-v1.yaml`](../../configs/protocols/p3.6-receipt-v1.yaml). The encoder stopped early
after 13 epochs on HDFS (best validation target NLL 1.666) and 8 on BGL (0.289). All seven baselines scored the
8,192 buffer windows of each fold; only the BGL singles of GTAT (1), P2.2 (19) and P2.3 (19) are UNKNOWN_REVIEW.
