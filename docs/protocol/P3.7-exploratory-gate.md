# P3.7 exploratory gate (FUS-GATE-001)

Spec: [`configs/protocols/fus-gate-v1.yaml`](../../configs/protocols/fus-gate-v1.yaml). Code:
`src/seqlogad/adaptation/synthetic.py` (synthetic copies and their scoring) and `src/seqlogad/adaptation/gate.py`
(features, training, report). Tests: `tests/test_gate.py`, `tests/test_adaptation.py`.

## Status: exploratory, G2 stays PARTIAL

G2 is PARTIAL (`configs/protocols/g2-signature.yaml`), so learned fusion is closed. On 2026-11-28 the researcher opened
P3.7 as an **exploratory** analysis (amendment P3.7-EXPLORATORY-001):

- The gate is trained and reported, with every table labelled EXPLORATORY.
- It supports no claim that fusion helps. `EQUAL_WEIGHT` stays the primary fusion and the mandatory comparator.
- The confirmation seeds are not used, because SEED-CONFIRM-001 forbids feeding them into Phase 3.

The researcher chose the self-supervised synthetic design over two alternatives:

- **Supervised gate:** it would need a C2 amendment, and has one labeled source per fold with 20 or 67 positives.
- **Documenting P3.7 as infeasible.**

## Design

- **Episodes.** One episode per source of each target fold (three per fold). The base windows are the 512
  checkpoint-selection windows of each source. DIV-P2-001 excludes these windows, so no P2.6 result is reused, and no
  label is read.
- **Synthetic copies (seed 42).** Each base window gives a CLEAN copy and up to three mutated copies.

  | Copy | What changes | Expert family aimed at |
  |---|---|---|
  | `FOREIGN_TARGET` | the target message becomes the target message of a window of another source | semantic and sequence |
  | `SHUFFLED_CONTEXT` | the context messages are put in a seeded order that differs from the original; skipped when fewer than 2 distinct context messages | sequence |
  | `FOREIGN_TOPOLOGY` | the component and location of every record become those of another source's window | structural |

  An expert scores only the copies whose input differs from CLEAN; the others reuse its CLEAN score.
  - P2.1 to P2.3 score on a Colab GPU (`colab/P3.7_Gate/P3.7_Synthetic.ipynb`).
  - P2.4 scores on the local CPU, on its graph records. Some ARCH-HADOOP graph contexts leave out records of the
    sequence context; under SHUFFLED_CONTEXT, each sequence-context record that the graph contains takes the message
    the sequence experts see at that position.
- **Gate.**
  - **Model:** an MLP 8 → 32 → 16 → 3 with a softmax over the families that have a score: SEMANTIC (P2.1), SEQUENCE
    (the mean of P2.2 and P2.3, with no selection between them) and STRUCTURAL (P2.4).
  - **Inputs:** the 8 features of the spec, against the system's normal reference. For a source episode that is its
    training windows and its CLEAN copies; for the target it is ADAPT-MEM-001, CAL-CS-001 and UNC-CS-001.
  - **Objective:** a paired ranking loss, CLEAN against mutated.
  - **Training:** the epoch count is chosen by leave-one-episode-out; the gate is then trained on all three episodes.
- **Report.**
  - Held-out-episode AUROC of mutated against CLEAN for the gate, equal weight and each family.
  - Gate weights by mutation.
  - Gate outputs on the target buffer, as example outputs.
  - The target evaluation runs only in the locked final run (G4).

## Limitations

- The experts were trained on every source of the fold, so an episode varies the system, not the experts' exposure.
- The checkpoints were selected on these windows (with labels, under C2), so the expert scores on them may be
  optimistic.
- Synthetic anomalies test the mechanism, not the population of real anomalies.
- The episode scales come from at most 512 CLEAN windows, below CAL-CS-001's minimum of 1,000.
