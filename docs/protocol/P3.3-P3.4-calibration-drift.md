# P3.3 calibration (CAL-CS-001) and P3.4 drift (DRIFT-CS-001)

Specs: [`configs/protocols/cal-cs-v1.yaml`](../../configs/protocols/cal-cs-v1.yaml),
[`configs/protocols/drift-cs-v1.yaml`](../../configs/protocols/drift-cs-v1.yaml). Code: `src/seqlogad/adaptation/`
(`calibration.py`, `drift.py`, `store.py`). Tests: `tests/test_adaptation.py`.

Opened by the researcher on 2026-11-27 (workbook update P3.3-P3.4-STATUS-001, K23 and K24 → In progress) to
preregister both tasks while P3.2 waits for its GPU buffer pass. Both specs were written before any P3.2 buffer
score was summarised: the P2.1–P2.3 pass had not run, and the local GTAT buffer scores were not inspected. Both
tasks run only on a **frozen** fold memory (`memory.json` of ADAPT-MEM-001), so nothing runs until P3.2 is done.

## P3.3: CAL-CS-001

The experts' raw scores live on unrelated scales: a log-likelihood, a reconstruction error, a GTAT score. CAL-CS-001
puts them on one target-normal scale, per target fold, without any label:

    score_calibrated = (score_raw − q50) / (q99 − q50)

Here q50 and q99 are the median and 99th percentile of the expert's scores on the fold's burn-in buffer windows
(buffer_scores, about 8,192 windows; ABSTAIN windows are left out). A calibrated score of 0 means "as typical as the
median normal window", and 1 means "as high as the top 1% of normal windows", for every expert.

- **Why this rule.** It is strictly increasing, so each expert keeps its ranking and its single-expert metrics. No
  score saturates, unlike a pure empirical-CDF rank. The 99th percentile still has about 82 buffer windows above it,
  so it is stable; the 99.9th would have about 8.
- **Next to it.** A tail p-value (1 + #{reference ≥ s}) / (n + 1) is reported for reading and for P3.5. It never
  replaces the calibrated score.
- **No fallback.** If q99 ≤ q50, or fewer than 1,000 reference windows exist, the expert is DEGENERATE_SCALE or
  INSUFFICIENT_REFERENCE for that fold and gets no calibrated score. No other anchor is tried.
- **Sanity checks.** All are label-free, reported, and never used to change the rule:
  - the anchors are reproduced;
  - the ranking is preserved;
  - a chronological split: anchors from the first half of the buffer, and the share of the second half above that
    q99, which is STABLE inside [0.5%, 2%];
  - a histogram of calibrated buffer scores, in place of plots (no plotting dependency).
- **Output.** `data/processed/adaptation/CAL-CS-001/<fold>/` holds `artifact.json` and `reference.parquet`. It is
  written once, made read-only, and bound to the memory key, the `memory.json` hash and the spec hash. Envelopes are
  not rewritten; consumers apply the frozen table.

## P3.4: DRIFT-CS-001

Everything is measured against the frozen buffer memory. Nothing is ever refitted on evaluation records.

| Level | Measure | Reference |
|---|---|---|
| Window | event coverage: share of the window's records whose event is in the buffer | `statistics/unigrams` |
| Window | transition coverage: share of the window's consecutive pairs seen in the buffer | `statistics/transitions` |
| Window | topology coverage: share of graph-node attribute values (component, severity, location) seen in the buffer | `statistics/node_attributes` |
| Window | prototype-distance p per expert: how unusual the distance to the nearest buffer prototype is | `prototypes` |
| Block of 512 windows | event JSD, unseen-event rate, unseen-topology rate | 64 buffer blocks, leave-block-out |
| Fold × expert | source-to-target gap: KS distance and median shift of raw scores, P2.6 source windows against buffer windows | P2.6 evidence, descriptive only |

- **Thresholds.** For each block statistic, the threshold is the largest value among the buffer's own 64
  chronological blocks. Each block is scored against the buffer with its own records removed, so the thresholds
  capture normal within-buffer variation.
- **Online state.** An evaluation block whose statistic exceeds a threshold gets `DRIFT_REVIEW`; otherwise it is
  `IN_REFERENCE`. The state is an output for review.
- **No silent recalibration.** CAL-CS-001, the memory and the thresholds stay unchanged. Any recalibration is a new
  versioned artifact that the researcher approves.
- **Limitation.** Leave-block-out removes only the block's own window records, so a rare event elsewhere in the
  buffer stays in the reference. This lowers the thresholds slightly, which means more reviews, never fewer.

A code smoke run on the frozen statistics component (no model score) took 4.5 s for HDFS and 12.7 s for BGL, with
64 reference blocks each. The rules above were fixed before it ran and did not change.
