# P2.5 — Common evidence contract EVID-CS-001

Status: implemented 2026-11-22. Code: `src/seqlogad/evidence/contract.py` (validator, single source of the
schema) and `src/seqlogad/evidence/convert.py` (one converter per native expert format).
Tests: `tests/test_evidence_contract.py`. Check real outputs:
`python scripts/validate_evidence.py <seqlogad_outputs_P2.x_S42_FINAL.zip> ...`.

P2.5 trains nothing and calibrates nothing. It fixes one envelope that every Phase-2 expert's evidence is
converted into, so P2.6 and P3 can read any expert alone or join experts without knowing their internals.
It implements the P2.0 §9 minimum envelope and the `evidence.required_fields` of `phase2-architecture-v1.yaml`.

## 1. Envelope

Every envelope has exactly these 25 fields; a missing or extra field is rejected.

| Field | Rule |
|---|---|
| `schema_version` | `EVID-CS-001` |
| `expert_id`, `expert_role` | one of the four experts with its fixed role (SEMANTIC, SEQUENCE ×2, STRUCTURAL_TEMPORAL) |
| `fold_id`, `architecture_id` | `FOLD-TARGET-ARCH-*`, `ARCH-*` |
| `unit_id`, `unit_kind` | expert unit id; `LOG_RECORD` (P2.1) or `TARGET_WINDOW` (P2.2–P2.4) |
| `record_ids` | non-empty, `ARCH-X:<rank>` of the same architecture, strictly chronological |
| `target_record_id` | the last record id: the record the score is about, and the join key across experts |
| `score_raw` | finite; `null` exactly when `status` is `ABSTAIN` |
| `score_direction` | `HIGHER_IS_MORE_ANOMALOUS` |
| `score_calibrated`, `calibration_status` | `null`, `NOT_CALIBRATED` (Phase 2 never calibrates) |
| `uncertainty`, `uncertainty_method` | `null` or ≥ 0; the method string is always present and, when uncertainty is `null`, says why |
| `coverage` | measurement in [0, 1], not a probability of correctness |
| `evidence` | list of `{kind, value, …scalars}`; non-empty unless `ABSTAIN` |
| `localisation` | list of scalar objects; positions and `*_rank` are non-negative integers; `target_rank` equals the target record |
| `status`, `reason` | `VALID` (reason `null`), `LOW_COVERAGE` or `ABSTAIN` (reason required) |
| `model_revision` | non-empty |
| `checkpoint_sha256`, `input_manifest_sha256`, `context_config_sha256` | 64-character SHA-256 hex |
| `expert_metadata` | scalars; must contain `native_schema_version` |

## 2. Units and joins

P2.1 scores one log line (`LOG_RECORD`). P2.2, P2.3 and P2.4 score the target record of a P2.2 window
(`TARGET_WINDOW`, same `unit_id` for all three). All experts therefore meet on
(`fold_id`, `target_record_id`). `index_by_target` validates one expert's envelopes, rejects duplicates and
mixed experts, and returns that index, so one expert is consumable on its own. Missing evidence is a missing
key or an `ABSTAIN` envelope, never a zero score.

## 3. Converters

| Native schema | Expert | Conversion |
|---|---|---|
| `SEMANTIC-EVIDENCE-1` | P2.1 | add unit kind, target record and metadata |
| `SEQUENCE-EVIDENCE-1` | P2.2, P2.3 | same; variant and context policy move to `expert_metadata` |
| `SEQLOGAD-EVIDENCE-DRAFT-P2.4` | P2.4 | `SCORED` → `VALID`; the three score parts become evidence items; the "uncertainty not estimated" reason moves to `uncertainty_method` |
