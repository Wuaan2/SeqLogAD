# P2.6 — Expert diversity preregistration (DIV-P2-001)

Status: frozen 2026-11-22, before any expert was scored on the evaluation units below.
Config: `configs/protocols/p2.6-diversity-v1.yaml`. Label scope: C2 amendment of 2026-11-22.
Question: does each expert add anomaly evidence beyond the best single expert, on source data, without any
target label? The answer feeds a **recommended** G2 verdict; the researcher signs G2.

## 1. Experts and checkpoints

P2.1 Semantic, P2.2 Sequence reference (V13R1), P2.3 Sequence lightweight, P2.4 GTAT, each with the
checkpoint selected inside its FINAL ZIP, unchanged. Nothing is retrained or re-selected. Seed 42 only, so
no multi-seed claim.

## 2. Evaluation units (held out from checkpoint selection)

- Pool: every sequence `SOURCE_VALIDATION` window of the fold (2,048 per source).
- Removed: the 512 windows per source that P2.2, P2.3 and P2.4 used for checkpoint selection
  (`select_windows(val, 512, seed 42)`), and, for HDFS, every window whose block occurs among those 512.
- Labeled units: HDFS blocks (unit score = mean of its windows) and BGL log lines (unit score = window score).
  Each fold has one labeled source: HDFS in the BGL fold, BGL in the HDFS fold.
- Hadoop and OpenStack windows: label-free diagnostics only.
- P2.1 scores the target record of each window; P2.2–P2.4 score the window. All meet on
  (`fold_id`, `target_record_id`) through EVID-CS-001.
- An ABSTAIN is excluded for that expert and counted in its coverage; it is never filled with zero.
- If a labeled source has fewer than 20 positive units in the evaluation set, its verdicts are
  INSUFFICIENT_POWER.

## 3. Metrics

| Level | Metric |
|---|---|
| Single expert | AP (primary, non-interpolated), AUROC, false-alarm rate at recall 0.5 and 0.8, coverage |
| Pair | Spearman ρ of unit scores; double-fault rate (share of positive units missed by both) and disagreement, with an alarm budget of the top 5% scored units per expert |
| Combination | Equal-weight mean of mid-rank percentiles (within fold, source and expert) over the experts that scored the unit; no learned weights |

Combinations evaluated: all singles, the best single plus each other expert, all four, and the paired
difference P2.3 − P2.2. "Best single" is the expert with the highest point AP on the evaluation set of
that fold; comparing against the maximum makes added evidence harder, not easier, to show.

Uncertainty: paired non-parametric bootstrap over labeled units, 2,000 replicates, percentile 95%
interval, seed 42.

## 4. Decision rules (fixed now)

Practical margin: ΔAP ≥ 10% of the best single expert's AP (relative, because base rates differ by source;
not inherited from EFFECT-001).

| Verdict per expert and fold | Rule |
|---|---|
| ADDS_EVIDENCE | ΔAP(best single + expert) − AP(best single) ≥ margin **and** the 95% interval lower bound > 0 |
| INSUFFICIENT_POWER | fewer than 20 positive units |
| NOT_SHOWN | otherwise |

Recommended G2: **PASS** if some non-best expert has ADDS_EVIDENCE in both folds, **PARTIAL** if in one
fold, **NOT_SHOWN** otherwise. Null and negative findings are reported in full.

## 5. Comparators (label-free, fitted on the same source's `SOURCE_TRAIN`)

| Comparator | Score |
|---|---|
| `unseen_rarity` | −log add-one frequency of the target message |
| `count_vector` | window unigram NLL under train message frequencies |
| `isolation_forest` | 1,024 hashed message counts per window, 200 trees, `random_state` 42 |
| `ngram_markov` | −log add-one bigram probability of the target given the previous record |

An expert that does not beat these is reported as such.

## 6. Label-free diagnostics (all four sources)

Spearman ρ, top-5% overlap, abstain and coverage, synthetic probe responses (mechanism diagnostics, not
population performance) and resources (parameters, runtime, peak VRAM, seconds per window).

## 7. Execution

1. GPU scoring pass on Colab: load each FINAL-ZIP checkpoint, score the evaluation windows of all sources
   in both folds, write EVID-CS-001 JSONL per expert and fold.
2. CPU analysis: comparators, metrics, bootstrap, report `DIV-P2-001`.

## 8. Forbidden

Target labels or data; retraining or re-selection; tuning any P3 weight, gate, threshold or calibration
from these results; choosing a sequence winner from P2.6 alone; an agent signing G2.
