# P2.4 — GTAT structural/temporal expert (GTAT-ST-001)

Status: preregistered 2026-11-21, before any graph view was built or any P2.4 run started.
Config: `configs/models/gtat-v1.yaml` (machine-readable; this document explains it).
Protocol: EXC-007 (target folds HDFS and BGL; Hadoop and OpenStack are source-only), seed 42, development run.
Satisfies the P2.0 contract §4 freeze list. It does not satisfy the SEQUENCE role
(`gtat_satisfies_sequence_role: false`), and it does not replace P2.2 or P2.3.

## 1. Purpose

P2.1 scores one log line; P2.2 and P2.3 predict the next log from at most 8 predecessors.
None of them sees elapsed time, recurrence structure, component/location topology or context
longer than 8 records. P2.4 scores the same units as P2.2 from a causal graph of up to 64
predecessors that carries exactly those signals. Its value is judged later by G2 diversity
and the `remove_structural_time` ablation; no gain is assumed here.

## 2. Model identity (resolves RSG-001)

"GTAT" in SeqLogAD is not a published log model. GTAT-ST-001 is a SeqLogAD design whose core is
GTAT, Graph Topology Attention (Shen et al., *Scientific Reports* 2025,
doi:10.1038/s41598-025-88993-3): node features and topology features form two streams that
exchange information through cross-attention. SeqLogAD adds, and owns, these modifications:

| Modification | Why |
|---|---|
| Typed directed edges with a learned per-head attention bias | Logs have several relations (next, recurrence, component, location, request) |
| Quantised Δt and age encodings | GTAT has no notion of time |
| Heterogeneous attribute nodes (component, location, request) | Topology beyond the event chain |
| Masked-target temporal/structural/event objective | Self-supervised, label-free scoring |
| Hashed text features, no id embeddings | Portability to unseen systems |

Logs2Graphs (L1) and LogGT (L7) informed the design; neither is reproduced or claimed.

## 3. Unit and data

- **Unit.** Exactly the P2.2 sequence windows: `window_id = sha256(architecture|partition|target_rank)[:24]`.
  P2.4 therefore reuses the source-development label sidecar (`885b5382…`) for checkpoint
  selection and aligns with P2.2/P2.3 evidence for fusion without new labels.
- **Context.** The ≤64 most recent records before the target in the **same P2.2 group**: HDFS block,
  Hadoop application, OpenStack instance (else GLOBAL), BGL GLOBAL. Causal only. Never crosses an
  architecture, partition or group. In GLOBAL groups the context stops at the first gap longer
  than 1 h, walking back from the target; this removes OpenStack capture-file boundaries (93,814 s).
  Hadoop stack-trace continuation lines in the context fold into their parent record
  (`continuation_lines` count); the target record is always kept as it is.
- **Membership and fields.** Membership comes from the semantic bundle (full source partitions).
  Fields come from the P1 adapters on the raw logs, joined by rank. Every node must match the
  bundled normalized message exactly, or the build fails. The 2026-11-21 feasibility check matched
  100% for all four sources.
- **Abstain.** A window with no context record (only possible after the gap cut) has status
  `ABSTAIN` and score `null`. Abstained validation windows are excluded from checkpoint selection
  and counted.

### 3.1 Graph view files (builder contract)

`graphs.parquet`, one row per P2.2 window of the fold (every source, train or val):

| Column | Type | Meaning |
|---|---|---|

| `target_rank` | int64 | target record |
| `context_ranks` | list[int64] | ascending, ≤64, all `< target_rank` |
| `status` | str | `SCORED` or `ABSTAIN` |

`nodes.parquet`, one row per (`architecture_id`, `partition`, `rank`) used by any graph of the fold:

| Column | Type | Meaning |
|---|---|---|
| `architecture_id`, `partition`, `rank` | str, str, int64 | key |
| `effective_ts` | int64 | µs, as in the P1 chronology |
| `event_text` | str | bundled `normalized_message` |
| `component_text` | str or null | normalised component words (config `component_text`) |
| `severity` | int8 | config `severity_map`, else −1 |
| `location` | str or null | BGL midplane `R##-M#`; grouping key only |
| `request_group` | str or null | keyed hash of the OpenStack request id; grouping key only |
| `continuation_lines` | int32 | Hadoop folded continuation lines, else 0 |

No other column is allowed. Session, trace and node ids, file names and labels never appear.
`graph-bundle.json` binds the semantic and sequence bundle SHA-256s, the fold `membership_sha256`,
the raw file SHA-256s, the bundled normalizer SHA-256, the builder git revision and the SHA-256 of
the canonical JSON of `graph_view`, and records `target_labels_read: false`, `label_columns: []`.

## 4. Graph construction (trainer, `seqlogad.graph.features.build_graph`)

Edges are derived deterministically at load time, so the view stores no edge list.

| Node type | One per | Features |
|---|---|---|
| OCCURRENCE | context record | event-text hash bag, component-text hash bag, severity, recurrence count so far, first-occurrence flag, Δt from previous record, age (Δt to last context record), offset from target |
| TARGET | the target | a learned mask vector and its offset; nothing else is visible |
| COMPONENT | distinct component text in context | component-text hash bag, member count |
| LOCATION | distinct BGL midplane in context | member count only |
| REQUEST | OpenStack request group with ≥2 context members | member count only |

| Edge type (source → destination) | Attribute |
|---|---|
| NEXT: record i → record i+1, last context record → TARGET | Δt bucket |
| RECURRENCE: previous occurrence of the same event → occurrence | Δt bucket |
| HAS_COMPONENT / COMPONENT_OF | — |
| AT_LOCATION / LOCATION_OF | — |
| IN_REQUEST / REQUEST_OF | — |
| CONTEXT: every context record → TARGET | age bucket |
| SELF | — |

No causal edge is inferred from adjacency. Order is explicit through NEXT edges and offsets, so
ABACA and ACABA give different graphs (required test).

**Time.** Timestamps are floored to whole seconds (the coarsest resolution shared by all four
systems), Δt is clipped at 3600 s and bucketed at lower bounds
0, 1, 2, 4, …, 2048, 3600 s. Raw Δt is never a feature: its resolution identifies the system.

**Text.** Lowercase `[a-z]+` tokens, at most 32 per text, keyed BLAKE2b-64 hashing into 16,384
(event) or 4,096 (component) buckets, mean embedding bag. No vocabulary or id embedding exists, so
unseen systems need no new parameters.

## 5. Model

Three GTAT layers, hidden 128, 4 heads, FFN 256, dropout 0.1, random init, at most 5M parameters.
Each layer keeps a node stream H (text and severity) and a topology stream T (type, counts, degree,
time and offset features). H attends to T and T attends to H (cross-attention), each restricted to
graph edges, with a learned bias per head for each edge type and Δt/age bucket. The TARGET node's
final H and T states feed three heads.

## 6. Objective and score

The target is fully masked. From the context graph the model predicts:

| Head | Classes | Evidence |
|---|---|---|
| `temporal_delta_bucket` | 14 Δt buckets from the last context record | arrival-time surprise (bursts, stalls) |
| `recurrence_pointer` | the most recent context record with the same event, or NEW | structural surprise |
| `event_class` | BLAKE2b(event text) mod 4,096 | content surprise |

Loss = sum of the three cross-entropies. Within each batch the 5% highest-loss graphs are dropped
(trimmed loss), because unlabeled source training data is not assumed clean.
Score = the same sum in nats, higher is more anomalous; the three terms are also reported
separately as evidence components.

## 7. Training and selection

- FP32 (TF32 off), AdamW lr 1e-3, weight decay 0.01, 300 warmup steps then linear decay,
  at most 6,000 steps, 32 graphs per source per batch (96), gradient clip 1.0.
- Train graphs: every `SCORED` train window of the fold, sampled uniformly per source with replacement.
- Validation: the same 512 windows per source that P2.2/P2.3 use (`select_windows`, seed 42).
- Every 250 steps: checkpoint, then selection by macro F1 on labeled **source** validation units
  (HDFS block, BGL line), as in the P3.1 amendment. Target labels are never read.
  Early stopping after 6 evaluations without improvement; ties keep the earliest step.

## 8. Coverage and evidence

Unit coverage = context records with both a component and a known severity / context records.
Missing fields create no node or an unknown token, never an imputed value. Coverage, status and the
three score components are written per scored window. Missing graph coverage never removes or
overrides the explicit sequence experts.

## 9. Risks fixed before training

| Risk | Rule |
|---|---|
| OpenStack capture boundaries encode the abnormal file | GLOBAL-group gap cut at 1 h |
| HDFS block id, Hadoop application/container ids are label units | grouping only, never features |
| Thread names and request ids identify jobs | Hadoop thread names unused; requests hashed, grouping only |
| BGL severity is a strong prior (FATAL 23.7% of train) | legitimate field; `no_severity` ablation in P4 |
| Component strings and time resolution identify the system | hashed text, 1 s time, per-source batch balance |
| Hadoop validation is one application (92%) | per-source metrics reported |

## 10. Required tests and planned ablations

Tests: ABACA/ACABA order collision, causal context only, no id features, label-free view,
parameter budget, checkpoint round trip.
Ablations (P4, not run here): `remove_structural_time`, `no_severity`, `no_component_nodes`,
`no_recurrence_edges`.

## 11. Not claimed

No target metric, no superiority over P2.2/P2.3, no claim that GTAT-ST-001 reproduces GTAT,
LogGT or Logs2Graphs, and no multi-seed stability.
